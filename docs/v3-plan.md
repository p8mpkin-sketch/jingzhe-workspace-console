## 1. 现状审计与重复地图

### 1.1 V2 是什么

哈希路由下的 14 个路由（`app/src/app/App.tsx`），一个常驻外壳（232 px 导航栏加 52 px 顶栏），

## 2. 三个视觉方向

静态研究稿：`design/v3-directions.html`（`?d=a|b|c&t=light|dark`）。同一屏（工作台 › 运行 › Agent 轨迹）
的渲染图在 `docs/screenshots/v3/directions/`。这些图画的是最初的方向 A；cz 在 2026-11-23 把它修订为 **A+**，
下面的文字以 A+ 为准，信息架构、项目合并、任务合并和报告工作区都不受这次修订影响。

### A+. 活的仪表面板（Living Instrument Panel）— **选定**

骨架沿用方向 A：用细线分隔的面板而不是画布上的卡片，横向标签行，等宽对齐的数据，停靠在面板底部的输入框。
方向 A 的问题是轨迹只是一张平铺的带格线日志：安静，但不“活”。对比度偏弱，没有阶段结构，看不出当前阶段，
动效只有淡入。A+ 用真实的结构和真实的状态变化让仪表活起来，而不是靠装饰：

- **运行条（Run Strip）**：一条横向的阶段条，分已完成 / 进行中 / 未开始，带真实的步数和耗时，可以点击跳转或筛选。
  全屏只有进行中的那一个阶段有一个脉动点。
- **阶段堆栈（Stage Stack）**：轨迹按阶段分组。进行中的阶段展开；已完成的阶段收成一行摘要（数量和耗时）；
  未开始的阶段隐藏或以占位形式出现。用户自己展开的阶段不会被自动收起。
- **五种轨迹行**：判断、工具调用、风险发现、审批、阶段结果 / 错误。每种有自己的图形形状和行内结构，
  不只靠颜色区分。
- **联动的检查器**：和主面板是同一种表面语言，用分隔线而不是嵌套卡片；主面板里选中的行和待审批项在检查器里同步。
- **有分量的输入框**：读起来是一条控制条，上下文标签在输入区上方，运行时有真实计时，发送 / 停止是主操作。
- **对比度**：事件正文用 ink，次要信息用 ink-2，时间用 muted 但保证可读；不用降低不透明度的方式做弱化。

密度仍然来自对齐和等宽数字；层次来自六级表面和一种浮层阴影；“活”来自阶段在推进、行在分类、状态在联动。

### B. 编辑式运营（Editorial Operations）

一条阅读栏，36 px 的标题直接陈述现状，数量写在页边注里，留白充足，轨迹写成叙述段落。安静、易读。

### C. AI 原生画布（AI-Native Canvas）

输入框在屏幕中心，轨迹是一条对话线，上下文和“需要你处理”作为卡片浮在两侧，导航退成胶囊。

### 决定

**选 A+。** 两个核心界面是实时工作台和任务表，都是“比较和扫视”的工作：行很多，有几列数字，状态在你看的时候会变。
A 系是唯一以对齐的行为基本单位的方向；A+ 在此之上补上了阶段结构和状态反馈。

**B 为什么落选。** B 就是 V2 自己声明的方向（“editorial operations console”），选它等于换皮。
更重要的是，阅读栏天生就窄，而需求明确排除了窄的主工作区；叙述段落还会把操作者要比较的东西（时间、耗时、状态）藏起来。
B 只在一个以阅读为本的地方保留：报告阅读器，它是 A+ 框架里的一块排版界面。

**C 为什么落选。** 十四个路由里只有两个是对话。把输入框放在中心，会让发现、证据、产物和任务降为二等，
会把 500 条事件的轨迹变成一墙气泡，而浮动卡片正是需求排除的“一堆浮动卡片”。
C 真正的贡献是上下文标签、命令菜单和一个强输入框，这些是组件而不是布局；它们做成 `Composer`，停靠在 A+ 的面板里。

**原始的 A 为什么不够。** 它把“安静”做成了“平”：所有事件同一种行、同一种灰度，操作者看不出评估走到了哪里、
哪一行需要他。A+ 不加任何霓虹、扫描线、光晕、粒子或装饰性循环；它只增加结构（阶段）、类型（五种行）和反馈（状态变化的动效）。

这不是混搭：布局、表面、密度和字阶全部来自 A 系。阅读器和输入框是它承载的两种内容类型。

沿用 `CLAUDE.md` 的约束：暖中性画布、石墨色文字、靛蓝主色、青绿表示健康、琥珀表示注意、红色只用于阻断性失败；
字体为 Instrument Sans / Inter / IBM Plex Mono，不新增字体。`CLAUDE.md` 的“visual target”一行在阶段 1 更新为 V3 方向，
并写明唯一允许的循环动画是运行条上进行中阶段的那一个脉动点（见 6.5）。

| 主标签 | `shell/WorkbenchTabs`（读 `ia.ts`） | 六个标签；“风险发现”上带数量；有审批等待时“运行”上带提示点 | — |
| 二级栏 | `shell/SurfaceBar` | 二级标签、分段切换、一个实时状态位 | 汇总标签（D11） |
| 检查器 | `shell/Inspector` + `useInspectorState` | 复核队列（审批加当前检查对象）、简报（任务简报、模型路由、任务状态）、进度（阶段、五轮复核及重算）、日志（最近事件） | 发现、报告、指标 |
| 降级提示 | 现有组件 | 哪些数据源失败、重试 | — |

检查器的行为：

- 1280 px 及以上是停靠列（把主界面往左推，不遮挡任何东西）；1280 以下是带焦点陷阱的抽屉；760 及以下是全宽底部面板。
- 宽度 280–480 px，拖动分隔条，或让分隔条获得焦点后按 ← / →（`role="separator"`，`aria-valuenow`）。双击恢复为 320。
- 开合状态、宽度和上次所在的标签按用户保存（`jz.inspector.<username>`）。
- 在工作台任何位置按 `Ctrl/⌘ + .` 可以开合；抽屉形态下 Escape 关闭并把焦点还给开关。标签是 `tablist`，支持方向键。
- 只有在抽屉形态下，切换主界面时才会自动关闭。
- 和主面板是同一种表面语言：同一级表面、同样的行高和字阶，分区用分隔线，不用嵌套卡片。
- 与主面板联动：主面板里选中的轨迹行或风险发现会成为检查器的“当前检查对象”；轨迹里的审批行和“复核队列”里的同一项
  是同一个对象，在任一处处理，另一处立即更新；在检查器里点一项，主面板滚动到对应的行并把它标为当前行。

各宽度下的布局：1440 时检查器可选停靠；1024 时检查器是抽屉，标签放得下；760 时页头折成两行，读数保留状态和阶段；
390 时主标签在自己那一行里横向滚动，二级标签叠在分段切换上方，一次只显示一个界面。

**运行条**（`surfaces/runtime/RunStrip`，数据来自 `useWorkbenchData` 的 `stages`、`steps`、`currentStage`）：

- 每个阶段一格，三种状态：已完成（✓ 加耗时）、进行中（◐ 加“第 n 步，共 m 步”和已用时）、未开始（○，占位样式）。
  步数和耗时都来自真实的步骤时间线；没有步数的阶段不显示进度条，也不伪造百分比。
- 点击一格：把阶段堆栈滚动到该阶段并展开它；按住 Shift 点击（或格上的“只看此阶段”菜单项）改为筛选，只显示这一个阶段，
  再点一次取消。键盘：整条是一个 `tablist` 式的方向键组，Enter 跳转，Shift+Enter 筛选。
- 全屏只有一个脉动：进行中阶段格子上的 6 px 点（见 6.5）。暂停、等待登录、已中断时不脉动，改为对应的静态图形。
  `prefers-reduced-motion` 下不脉动。
- 760 px 以下运行条在自己的行里横向滚动，进行中的格子始终滚到可见位置；390 px 时只显示图形和阶段代号，耗时在堆栈的阶段行里。

**阶段堆栈**（`surfaces/runtime/StageStack` + `StageSection`）：

- 进行中的阶段默认展开，它的阶段行吸顶。已完成的阶段收成一行摘要：事件数、风险发现数、审批数、耗时。
  未开始的阶段合成底部一行占位（阶段名用 muted 文字加虚线边框表示，不靠降低不透明度），可以展开看“这个阶段会做什么”。
- 阶段完成时，它在 240 ms 内收成摘要行，下一个阶段展开。**用户自己展开过的阶段永远不会被自动收起**：
  每个阶段记一个“用户已展开”标记，自动收起只作用于没有这个标记的阶段。用户自己收起的阶段也不会被自动展开。
- **跟随**：开启时，新事件到达会把列表滚到底。用户向上滚动即暂停跟随，并出现“n 条新事件 ↓”按钮；点它或滚回底部恢复跟随。
- **固定**：把当前查看的阶段固定住。固定后阶段推进不会改变展开状态和滚动位置，运行条上那个阶段带一个图钉标记；
  取消固定后回到跟随逻辑。
- **追加事件时布局不移动**：列表虚拟化并且贴底；不在跟随状态时，新行追加在视口之外，视口里已有的行的位置不变
  （用滚动锚定实现，追加前后比较首个可见行的偏移）；输入框的高度在列表之外，不参与列表布局。

**五种轨迹行**（`surfaces/runtime/TraceRow`，每行：等宽时间列、图形列、正文、右侧的耗时或优先级、悬停和聚焦时的复制与深链）：

| 行类型 | 图形（形状） | 结构 | 特殊处理 |
| --- | --- | --- | --- |
| 判断 | ◆ 实心菱形 | 一句结论；推理过程默认折叠，可展开 | — |
| 工具调用 | ▸ 三角 | 工具名（等宽）+ 一行结果摘要 + 耗时 | 可展开为输入 / 输出两块，放在凹槽（inset）里的等宽文本，可复制 |
| 风险发现 | ▲ 实心三角 | 标题 + 证据数 + 状态 + 优先级文字 | 橙色左竖线是每一条风险发现的身份线；严重度由线宽、文字和一个小形状标记表达（见下）；“打开”跳到风险发现并选中它；不使用红色 |
| 审批 | ■ 实心方块 | 要批准的动作 + 批准 / 拒绝 | 抬升的表面（raised）加细边框，是轨迹里唯一有底色的行；有明确的主操作；处理后落回普通行并写明结果和处理人 |
| 阶段结果 / 错误 | ● 实心圆 / ✕ 叉 | 步骤或阶段的结果 + 耗时；错误给出完整原因 | 错误行有红色左竖线和“错误”文字标签，原因全文可选中，不放进悬停提示 |

**风险发现行的严重度**（橙色表示“这是一条风险发现”，不表示严重度）：

| 严重度 | 左竖线 | 形状标记 | 文字 |
| --- | --- | --- | --- |
| 严重、高 | 橙色 3 px | 竖线顶端一个实心小顶帽（比线宽，贴着行的上边） | “P0 严重”“P1 高”，字重 600 |
| 中、低、提示 | 橙色 2 px | 无 | “P2 中”“P3 低”，字重 400 |

红色保留给错误、被阻断的操作和破坏性操作，任何风险发现都不使用红色（包括风险发现表格和徽标里的“严重”）。

**操作者引导**是“判断”行的一个变体，不是第六种行：

| 属性 | 取值 |
| --- | --- |
| 行类型 | 判断（`data-row-kind="judgment"`） |
| 变体 | 操作者（`data-row-variant="operator"`） |
| 作者 | 操作者（`data-author="operator"`）；Agent 的判断是 `data-author="agent"` |
| 图形 | ◇ 空心菱形（Agent 的判断是 ◆ 实心菱形） |
| 可见标签 | “引导”（Agent 的判断是“判断”），行右侧写操作者的用户名 |
| 筛选 | 轨迹的筛选里有“操作者”一项，可以只看引导，也可以排除引导 |
| 计数 | 不计入 Agent 的判断数；阶段摘要可以单独写出，例如“41 条事件 · 12 条判断 · 2 条引导 · 4 条风险发现” |

当前行（键盘焦点所在或检查器正在查看的行）用 surface-2 底色。行的种类始终同时由图形形状和类型文字表达。

**空状态**（任何时候都不留下一大块空白面板）：

- 进行中的阶段还没有事件：显示这个阶段真实的待执行步骤列表（来自步骤时间线里状态为未开始的步骤），第一步标为“即将开始”。
- 评估还没启动：说明为什么是空的（“评估尚未启动”），并说明启动后这里会出现什么（各阶段的名称和一句话说明），主操作是“启动评估”。
- 没有数据且无法得到（会话已关闭、数据源失败、无权限）：说明原因、哪一个数据源失败、能做什么（重试、打开任务输出）。
- 筛选之后为空：说明是筛选导致的，并给出“清除筛选”。

**终端**（`surfaces/runtime/TerminalSurface`，包住现有的 `VirtualTerminal`）：虚拟化输出，跟随并在向上滚动时暂停，
带匹配数量和上一个 / 下一个的搜索，复制选区或全部，清屏（仅视图），全屏，换行开关，会话支持时提供命令输入；
一行状态说明 运行中 / 等待 / 失败 / 未连接。

**接口与请求**（`surfaces/runtime/RequestsSurface`）：分段为 接口资产 | 代理流量；一行筛选（方法、主机、状态、文本）；
选中一行会在详情抽屉里打开该请求（不是行内展开）；桥接和插件的健康状况写在一行状态里；
空状态和不可用状态说明缺的是什么（没有设备、未设置代理、还没有捕获到流量）。

没有假装打字的骨架文字，没有不以步数为依据的进度条。停止就是输入框的停止；引导发送失败时出现重试。

### 6.4 布局

8 px 网格（4 px 半步只用于密集行）。一种页边距：24 / 16（≤ 1100）/ 12（≤ 760）。

工作页面用满宽度；文章类内容（阅读器、Markdown）在全宽框架内限宽 760 px。

### 6.5 动效

动效只用来说明状态发生了变化。

| 令牌 | 数值 | 用途 |
| --- | --- | --- |
| `--jz-motion-instant` | 80 ms | 按下 |
| `--jz-motion-fast`（`hover`） | 120 ms | 悬停、焦点环、选中填充、新事件进入 |
| `--jz-motion-base`（`expand`） | 180 ms | 步骤变化、审批行抬升、展开收起、标签指示条、检查器开合 |
| `--jz-motion-slow`（`page`） | 240 ms | 阶段完成、抽屉、对话框 |
| `--jz-motion-pulse` | 1600 ms | 运行条上进行中阶段的脉动点，全应用唯一的循环 |
| `--jz-ease` | cubic-bezier(.2, 0, 0, 1) | 默认 |
| `--jz-ease-exit` | cubic-bezier(.4, 0, 1, 1) | 离开 |

| 事件 | 动效 |
| --- | --- |
| 新事件 | 120 ms 淡入加 4 px 上升（只用 `opacity` 和 `transform`，不改变布局）；没有光标，不逐字显示 |
| 步骤变化 | 180 ms：运行条的进度线推进一格，阶段行里的“第 n 步”数字交叉淡化 |
| 阶段完成 | 240 ms：该阶段的图形由 ◐ 变为 ✓，内容收成摘要行（用户展开过的不收），下一阶段展开 |
| 审批出现 | 180 ms：该行从普通表面过渡到抬升表面（底色和边框），不位移 |
| 跟随 | 跟随时新事件滚到底；用户向上滚动立即暂停跟随，出现“n 条新事件 ↓” |
| 选中 | 背景填充 120 ms |
| 抽屉 / 对话框 | 位移 16 px 加淡入，进入 240 ms，离开 180 ms |
| 检查器 | 开合时宽度变化 180 ms；拖拽时没有动效 |
| 任务状态 | 图形和文字交叉淡化 180 ms；行不移动 |
| 路由 | 内容透明度 120 ms；不滑动 |
| 脉动 | 只有一个：运行条上进行中阶段的 6 px 点，不透明度在 1 和 0.35 之间往复，周期 1600 ms；同一时刻全屏最多一个；暂停、等待、中断、完成时停止 |
| 减少动效 | `prefers-reduced-motion` 下所有时长为 0，状态变化立即完成；脉动点改为静态实心点；跟随滚动改为直接跳转 |

循环动画只有两处：上面这一个脉动点，以及请求进行中的骨架屏微光。没有霓虹、扫描线、光晕、粒子或任何装饰性循环。
流式追加时布局不移动：新行在列表末尾进入，`transform` 不参与布局；不在跟随状态时视口内已有行的位置保持不变。

### 6.6 图标

只用 Lucide。控件里 16 px，密集行里 14 px，导航栏里 18 px；所有尺寸的描边都是 1.5（`--jz-icon-stroke`）。
图标伴随文字出现；只有图标的控件带 `aria-label` 和提示，破坏性操作和主操作一定有文字。
状态图形是 `ui/StatusGlyph` 里的一组固定图形。

## 9. 风险与回滚

| 风险 | 可能性 | 影响 | 应对 |
| --- | --- | --- | --- |
| 某条重定向丢掉深链依赖的查询参数（`?view=`、`?tab=`、`?finding=`、`?masvs=`、`?taskId=`、`?sid=&cmp=`、`?focus=`、`?status=`、`?task=`） | 中 | 书签和通知链接失效 | 只用一个转发 `location.search` 的重定向组件；`check-redirects.mjs` 逐条覆盖；后端写出的链接（通知）继续可用，因为旧路径永久保留为重定向 |
| 统一后的项目详情对单应用项目调用公司项目接口 | 低 | 某个标签出现错误状态 | V2 已经能在 `/company/projects/:pid` 打开任何项目编号；每个标签各自加载、各自失败，不再用一个 `Promise.all` |
| 项目的“执行”标签需要按项目取任务，而没有这样的筛选 | 中 | 列表不完整 | 把现有任务列表和会话做关联（`task_id` → `project_id`），和 `/tasks` 今天的做法一样；在标签里写明“按会话关联”；不新增接口 |
| 报告工作区需要每个项目的项目报告 | 中 | N 个请求 | 复用现有的队列（并发 4）；只在范围需要时才取；写进请求地图 |
| 真实后端没有任务输出的日志接口 | 中 | “输出”只显示进度文本 | 界面说明数据来源并如实回退；不编造任何内容 |
| 输入框的上下文标签暗示了后端并不解析的结构化上下文 | 中 | 产生错误预期 | 标签序列化为可见文本，输入框明说 |
| 令牌数值的变化会在页面重新设计之前就影响每个页面 | 必然 | 中间阶段看起来只有一半是 V3 | 阶段 1 重新调校基础组件，让未改动的页面保持协调；每个阶段的截图都包含未改动的路由 |
| 懒加载路由闪现占位 | 低 | 感觉变慢 | 骨架屏按页面框架定尺寸；鼠标悬停导航项时预取 |
| 夹具的数据形状和真实后端不同 | 中 | 回归只在宿主机上才看得到 | 金丝雀评审前重跑真实读 / 写审计 |
| 工作台审计选择器（`data-wb-*`）位置变化 | 必然 | 审计脚本失效 | 钩子保留在新元素上；脚本和标记在同一次提交里改 |
| 范围：十个阶段在一个分支上 | — | 评审量大 | 每阶段一次提交，各自可运行、可单独回退 |

回滚：

- **按阶段：** `git revert` 该阶段的提交；各阶段依赖阶段 1，除此之外只依赖自己的文件
  （阶段 7 的 `TaskTable` 通过一个薄适配层被阶段 2 的“执行”标签使用，该适配层可回退为普通表格）。
- **金丝雀：** 金丝雀提供的是一个构建目录；把上一份 `dist` 留在新的旁边，回滚就是换一下目录。
  `BuildVersionGuard` 本来就会提示已打开的标签页刷新。
- **生产：** 不动。8099 端口继续提供旧前端，直到金丝雀通过验收清单并且 cz 说可以替换。
- **路由：** 旧路径保留为重定向，所以把前端回滚不会让 V3 期间产生的链接悬空，
  只有三条新路径例外（`/projects/…`、`/tasks/:id`、`/evidence`），回滚后的构建会通过现有的兜底路由把它们送到概览页。
